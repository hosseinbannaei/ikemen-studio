## Asset Management System - Architectural Roadmap
Looking forward, we brainstormed the foundation for a robust Asset Management System to manage characters, stages, motifs, and sounds seamlessly.

### 1. The "Global Asset Vault" (Storage & Sharing)
- **Concept**: A centralized library stored in the local app data directory (e.g., `vault/chars`).
- **Optimization**: Instead of duplicating 50MB characters across multiple projects, Ikemen Studio will utilize **Symlinks** or Hardlinks. Projects can "subscribe" to a vault asset, saving immense disk space and allowing global asset updates.

### 2. The Asset Parser (Go Backend)
- **Metadata Extraction**: A Go parser to read `*.def` files (e.g., `kfm.def`) to extract `displayname`, `author`, `versiondate`, and `mugenversion`.
- **Sprite Extraction**: A lightweight Go-based `.sff` parser designed specifically to extract the small roster portrait (Sprite 9000,0) and large VS screen portrait (Sprite 9000,1) to serve to the frontend as base64 images.

### 3. The Roster Editor (`select.def` Manager)
- **State Management**: The backend parses `data/select.def` into a structured, editable grid layout.
- **Adding/Disabling Assets**: The system will intelligently inject characters into empty slots, or disable them by commenting them out (e.g., `;ryu`) without deleting project files.
- **Visual Drag-and-Drop**: The Svelte frontend will implement a visual grid (using tools like `svelte-dnd-action`) mapped with the extracted SFF portraits, allowing users to physically drag characters to reorganize their selection screen.

### 4. Stage & Music Mapping
- Full UI support for managing `[ExtraStages]`.
- A "Properties" sidebar in the character editor to assign specific home stages and music tracks (`kfm, stages/dojo.def, music=sound/kfm.mp3`).

### Proposed Development Roadmap
1. **Phase 1: The Parser & The Grid**: Write the Go logic to safely read/write `select.def` preserving user comments, alongside a basic list UI.
2. **Phase 2: The Visuals**: Implement the SFF portrait extractor to upgrade the UI to a fully visual drag-and-drop grid.
3. **Phase 3: The Vault**: Implement the global asset library and symlinking system for cross-project sharing.

## Complete Multi-Vault Asset Management System Implementation

We fully engineered and shipped the **Multi-Vault Asset Management System**:

1. **Decentralized Multi-Vault Engine (`pkg/vault/`)**:
   - `pkg/vault/types.go`: Data models for `VaultManifest`, `VaultAsset`, `VaultInfo`, `Category` (`fighters`, `stages`, `motifs`, `sounds`), `LinkStrategy` (`symlink`, `hardlink`, `copy`).
   - `pkg/vault/manifest.go`: Safe atomic `vault.json` reading, creation, and writing.
   - `pkg/vault/manager.go`: Multi-vault lifecycle manager, global registry integration in `settings.json`, automatic default vault provisioning, and asset CRUD.
   - `pkg/vault/parser.go`: `.def` metadata parser (`displayname`, `author`, `versiondate`, `mugenversion`) and link/credits text scraper.
   - `pkg/vault/sff.go`: SFF v1 and SFF v2 binary reader extracting Sprite `(9000, 0)` and `(9000, 1)` into PNG thumbnails with fallback procedural avatar generation.
   - `pkg/vault/extractor.go`: Archive ingestion (`.zip`, `.tar.gz`, folders) with normalization, multi-asset pack detection, and package source tracking.
   - `pkg/vault/linker.go`: Non-destructive linking engine connecting vault assets into project `chars/` and `stages/`, updating `data/select.def`.
   - `pkg/vault/vault_test.go`: Complete suite of Go unit tests covering manifest I/O, parsing, zip ingestion, and project linking.

2. **Frontend UI Components & Store (`frontend/src/`)**:
   - `frontend/src/lib/stores/vaultStore.ts`: Full reactive store for multi-vault state, filtering (categories, tags, search query), asset updates, and ingestion queue.
   - `frontend/src/lib/components/VaultView.svelte`: Main Asset Vault dashboard with vault selector, category counts, tag pills, drag-and-drop ingestion dropzone, and responsive asset card grid.
   - `frontend/src/lib/components/VaultCard.svelte`: Asset card with preview portrait, category/version badges, author, tag chips, and quick actions.
   - `frontend/src/lib/components/VaultInspector.svelte`: Slide-out metadata editor for editing names, authors, source URLs, licenses, tags, notes, and asset deletion.
   - `frontend/src/lib/components/CreateVaultModal.svelte`: Modal to create new vaults or mount existing directories.
   - `frontend/src/lib/components/IngestPackModal.svelte`: Dissection modal for full games and multi-asset packs ("Dedicated Standalone Vault" vs "Extract to Current Vault").
   - `frontend/src/lib/components/AddFromVaultModal.svelte`: In-project modal to search across vaults and link fighters/stages into the active project with 1 click.
   - `frontend/src/lib/components/Sidebar.svelte` & `frontend/src/App.svelte`: Integrated "Asset Vault" into the main application navigation.
   - `frontend/src/lib/components/ProjectWorkspaceView.svelte`: Added "+ From Vault" buttons in the workspace toolbar and asset shortcuts.
